# 运行结果与定向发布完整性

- Status: Accepted
- Date: 2026-10-23
- Scope: 执行收尾、历史分页、systemd 定向发布及本地源码归并

## Context

持久化转入线程后，取消可以发生在运行结果已经提交、健康状态与通知尚未结算的边界。历史失败筛选虽然有覆盖计数索引，按时间取摘要仍可能逐行读取宽表。旧临时发布程序以整批标志判断回滚，并把接口错误与慢读一并忽略，且没有完成恢复点。

## Evidence

取消注入复现已保存 failed 记录但健康更新、通知调用均为零。线上真实页面查询计划使用项目/来源/时间索引，SQLite VM 在限制条数之前从 runs 表读取 status。临时目录故障注入证明：首文件替换、后续文件失败时，旧整批标志仍为 false，首文件未恢复。上一发布的三个分页验收全部 HTTP 400，恢复点正式 manifest 仍为 pending。

## Decision

执行已产生结果后，使用唯一异步收尾任务完成结果、健康与通知结算；重复取消不能切开该流程，返回原始结果，避免 watchdog 再制造一次失败。执行尚未产生结果时保留原取消处理；进程崩溃仍由原启动恢复负责。

常用类型、状态及时间筛选先通过已有覆盖索引物化本页 ID，再按主键读取最多一页摘要。保持精确总数、同一读快照、排序、分页和项目范围；其他筛选保留原语义。无需新增索引或迁移。

定向发布在任何替换之前持久化完整逆操作；部分替换失败也逐项恢复并核对摘要。接口验收必须带项目头和真实来源筛选，功能失败不降级为性能观测。成功后调用正式备份完成流程；备份保留失败不能回滚已接受源码。使用现有 systemd 和依赖，不修改在线数据库或主服务 I/O 配额。

唯一本地工作树为 D:\project\PulseGuard。归并保留两个目录的独有文件，冲突原件和旧工作树归档，不将临时资料或本地数据库作为发布源码。

## Alternatives considered

不通过无限放宽共享主机 I/O 配额掩盖查询放大；不新建多个大库索引；不在通用 storage.call 中吞掉取消，因为尚未交接的分配和 claim 仍需要原取消语义。

## Consequences

结果产生后的取消会等待有界的现有通知重试与存储结算。常用稀疏筛选仍需扫描窄索引，但宽行读取限制在本页。定向发布仅适用于无依赖、环境和结构变化的源码发布；这些变化仍需相应独立迁移、构建和恢复流程。

## Verification

回归覆盖结果持久化、健康更新和通知期间的重复取消、watchdog、收尾错误；稀疏筛选及有无来源条件、跨页与复杂筛选；部分文件替换、原本不存在的文件、部分恢复失败、HTTP 错误与项目范围、恢复点完成顺序。发布前执行隔离后端全量测试和前端构建，并保存生产副本预演与实际发布结果。

## Revisit when

需要进程崩溃下的可恢复通知投递、复杂筛选成为主要负载，或部署模型、依赖和数据库结构改变时重新评估。
