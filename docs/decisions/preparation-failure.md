# 前置准备与目标观测分离

状态：已采纳，2026-09-11

## Context

页面监控的前置脚本用于登录、获取数据和设置动态 URL。前置失败不能证明目标故障；其耗时也不能占用目标检查的超时额度。

## Evidence

原运行器将前置脚本、导航和校验包在同一个计时范围，前置异常沿目标失败路径更新健康状态。

## Decision

新增终态 `preparation_failed`（前置失败），失败来源 `preparation`。前置脚本执行、超时和目标 URL 解析失败保留错误和独立准备耗时，目标耗时为零，界面显示未执行。执行前的公共方法依赖预检失败同样属于此状态。该记录不参与健康、故障恢复通知和趋势统计，不将执行节点标为异常。

页面运行先准备，再开始目标导航和校验计时。沿用各阶段现有超时设置，前置阶段不消耗目标额度；节点调用等待预算包含独立准备时间。API 高级脚本目前仍是完整目标检查，没有推断其中哪些请求属于前置。

## Alternatives considered

继续使用目标失败会误报；标记成功会误报恢复；标记跳过无法表达明确的前置错误。

## Consequences

新增 API 状态值，前后端和执行节点需要使用本次版本才能完整呈现。复用既有 SQLite 文本列，启动时更新终态清理索引以覆盖新状态；旧记录保持原样，不根据错误文案重写历史。回退代码不丢失记录，但旧界面不能识别新增状态。

## Verification

回归覆盖前置报错、前置超时、不访问目标、独立计时、目标自身超时、远端结果传递，以及不更新健康和不发送目标通知。发布前运行后端测试、前端构建与页面验收。

## Revisit when

API 任务引入独立前置阶段，或实际出现需要持续运行旧协议的外部客户端时重新审视边界。
