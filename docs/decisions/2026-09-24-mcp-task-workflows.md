# MCP 批量执行与任务变更契约

- Status: accepted
- Date: 2026-09-24
- Owners: PulseGuard maintainers
- Scope: single-instance SQLite, runner, HTTP API, MCP
- Supersedes: extends [运营与保留策略](2026-09-24-mcp-run-history.md)
- Superseded by: none

## Context

用户要求批量幂等执行及完整任务编辑。HTTP 超时不证明任务未执行；直接重复提交可能产生真实目标副作用。
配置编辑同时需要避免覆盖其他客户端的新修改，并在提交前展示变更。

## Evidence

- 现有 `runner.run_check` 是 UI/API/脚本及远端节点执行的共同入口。
- `storage.write_transaction` 串行化 SQLite 写入，任务版本表及审计表已有持久化责任。
- MCP 无法从断开的 HTTP 连接判断外部请求是否生效；不应以客户端重试实现幂等。

## Decision

1. 添加项目内唯一幂等键及批次项目表，最多100个任务、全实例1000个未完成项、两个派发协程。
   同键同任务集合返回原回执，不同集合拒绝。整批范围检查与持久化原子提交。
2. 派发前持久化 running，核对已确认任务配置摘要；变化或禁用则拒绝。进程中断后的 running
   标为 unknown，不自动重跑。这保证同一已保留回执的至多一次派发，不承诺外部副作用恰好一次。
   项目变量、模块发布及外部目标状态不是配置摘要的冻结快照。
3. 已排队项可取消；已经派发的任务不撤销。回执包含独有 trigger 与关联运行 ID，轻量回执不自动过期。
   空闲轮询只读，维护期间暂停派发。数据库恢复使待派发项取消、在途项未知、待确认草稿失效。
   恢复历史数据库不能保留备份之后才生成的幂等键，操作者必须核对外部效果，不得盲目重提。
4. 创建/部分更新/版本恢复统一经过30分钟有效的服务端预览草稿，最多100个待确认草稿。
   输入支持完整 CheckCreate 字段；新任务默认禁用；不修改项目密钥、实例设置、模块定义或删除任务。
5. 更新以基准配置摘要做乐观锁，应用时再次验证；草稿摘要确认、版本快照、配置保存、审计、回执
   同一事务。重复应用返回原回执，调度同步允许重试。未知结果先查询原草稿，不创建新草稿重试。
6. 预览不执行脚本、不请求目标。脚本、请求头/体及断言等不透传原文，展示字段变化与不透明标记；
   未提供字段保持原值。已应用/取消/过期草稿清空候选配置，避免长期重复保留敏感数据。
7. MCP 默认15个只读工具；执行、配置、实例只读分别显式开启，全部开启29个。HTTP保持现有可信
   单实例/LAN部署边界，本次不新增互联网多租户认证保证。

## Alternatives considered

- 客户端自动重试执行：无法判定外部结果，拒绝。
- 声称恰好一次：目标没有共同事务/幂等协议，不成立。
- 内存队列与客户端预览：重启丢失回执，客户端可过期，拒绝。
- 通用工作流引擎/新数据库：当前单实例需求不需要额外基础设施。

## Consequences

- 可可靠查询提交与修改结果；配置变更有版本及审计，不直接覆盖并发更新。
- unknown 需要人工核查；记录增长需观察；任务内容保留仍遵循已有版本及备份策略。
- 部署采用增量表/列迁移，先备份并在活动数据库副本预检。依赖未变化，保持现有 systemd 与运行密钥。
- 回退代码不自动恢复数据库；先停止写入、核对回执及新数据，再执行明确获准的数据恢复。

## Verification

- `test_automation_workflows.py`：并发同键/不同集合、跨项目、禁用、配置变化、恢复失效、乐观锁、
   重复应用、过期、版本恢复、原子创建及调度重试。
- MCP stdio 到真实隔离 API/执行器：同键只执行一次，配置重复确认不增加版本，权限分离与脱敏。
- 后端全量门禁、前端构建与浏览器验收；生产使用备份、副本迁移、配置指纹及服务/API验收。

## Revisit when

- 多实例部署、任务队列吞吐量不足、回执增长显著，或需要目标系统参与的恰好一次协议。
- 需要冻结项目变量/模块版本或后台批量任务编辑时，另行明确快照与批量原子性边界。
